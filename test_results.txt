Test 36. A collision from my own test data, and a duplicate insert.

This is the case the collision requirement asks for. testdata/collision holds
a building file with Library, Science Building and Gym, and a facility file
with F004, F106, F009, F100, F010 and a lowercase duplicate f004. With a
capacity of 11 and the hash h = (h * 31 + c) % 11, F004 and F100 both land in
bucket 6 while F009 and F010 both land in bucket 0, so five accepted records
produce two collisions.

Input: ./campus.exe testdata/collision with 1, 2 and F100, 0.
Expected: five accepted, one rejected, capacity 11, five entries, two
collisions, the duplicate adding nothing, and F100 found even though it is
absent from the sample data.
Actual:
    buildings.txt: 3 accepted, 0 rejected
    Warning: facilities.txt line 12: duplicate facility ID F004 (keeping the first record)
    facilities.txt: 5 accepted, 1 rejected (hash capacity 11, entries 5, collisions 2)
    testdata/collision/buildings.txt: 3 accepted, 0 rejected
    Error: could not open testdata/collision/connections.txt. Treating it as empty.
    testdata/collision/connections.txt: 0 accepted, 0 rejected
    Error: could not open departments.txt - treating it as empty.
    departments.txt: 0 accepted, 0 rejected
    F004 | Computer Lab A | Science Building | Computer Lab
    F106 | Collision Lab | Library | Computer Lab
    F009 | Room 205 | Science Building | Classroom
    F100 | Archived Room | Library | Classroom
    F010 | Research Help Desk | Library | Library
    Total facilities: 5
    Found: Archived Room | Library | Classroom
Result: pass. The count stayed at two after the duplicate, and the lookup of
F100 succeeded without scanning the facility list. The two missing files are
expected, because this test directory only provides buildings and facilities.
